# Task Manager

## Project Description

A responsive task management application built for the Vistula University Team Project assignment. It stores tasks in Supabase PostgreSQL and uses the Supabase REST API to create, retrieve, update, complete, and delete them.

## Technologies

- HTML
- CSS
- Vanilla JavaScript
- Supabase PostgreSQL and REST API
- GitHub Pages

## Application Features

- Retrieve and display persisted tasks
- Add a task with a required title and optional description
- Load the latest task data and edit an existing task
- Mark tasks completed or incomplete
- Delete tasks
- Show loading, success, setup, and error messages
- Responsive desktop and mobile layouts

## Database Structure

The application expects a Supabase table named `tasks` with these columns:

| Column | Expected type / behavior |
| --- | --- |
| `id` | Primary key generated by the database |
| `title` | Text; required by the application form |
| `description` | Text; may be empty |
| `completed` | Boolean; defaults to `false` |

The `id` column must be selectable and usable in REST filters. Configure Row Level Security and grants to match the intended users and access model.

## Supabase Setup

The working project URL and public publishable key are configured in `config.json`; the application uses the `tasks` table. If configuring a different Supabase project, update `supabaseUrl` and `supabasePublishableKey` in that file and ensure the table follows the structure above.

Only a public Supabase publishable key may be included in this frontend repository. Never put a service role key, database password, or other secret in client-side files. Configure Supabase Row Level Security carefully; this application does not implement user sign-in.
